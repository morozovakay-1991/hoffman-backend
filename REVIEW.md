# Review instructions

## Контекст проекта

hoffman-backend — Laravel API для мобильного приложения (Flutter) выпускников
Процесса Хоффмана и отдельного сайта личного кабинета (Next.js). Публичный API,
платежи (Stripe + CloudPayments), персональные данные пользователей, юрлицо
зарегистрировано в Германии.

## Что считать Important (🔴)

- Отсутствие проверки авторизации или уровня доступа на эндпоинте — см. три
  уровня доступа из раздела 4.1 ТЗ (без подписки / подписка без подтверждённого
  статуса выпускника / подтверждённый выпускник): контент или действие доступны
  пользователю, которому не должны быть доступны.
- Broken object-level authorization — запрос к чужим данным по id/uuid без
  проверки владельца (профиль, дневник, история платежей другого пользователя).
- Ошибки в биллинг-логике: отсутствие идемпотентности у вебхуков Stripe/
  CloudPayments (повторная доставка создаёт дубль или повторно проводит платёж),
  неверное сопоставление провайдера по стране/валюте, рассинхрон статуса
  подписки между сайтом и мобильным приложением.
- Персональные данные (email, телефон, ФИО, ответы дневника) уходят в логи,
  Sentry, тексты ошибок или ответы API там, где им не место.
- Небезопасная работа с секретами: хардкод ключа/токена, попадание .env или
  ключа провайдера оплаты в коммит или в ответ API.
- Миграция, которая ломает обратную совместимость без отдельного плана наката,
  или тихо теряет данные (перезапись вместо upsert там, где ожидается история
  — например история платежей, дневник).

Всё остальное — стиль, именование, мелкие рефакторинги, структура кода — не
выше 🟡 Nit.

## Не проверять — уже покрыто CI

- Форматирование и PSR-12 (PHP CS Fixer).
- Статический анализ типов (PHPStan level 5).
- Сам факт "тесты прошли" — не отчитывайся об этом, но проверяй, покрывает ли
  новый тест реальный сценарий (в т.ч. граничный из раздела 11 ТЗ), а не просто
  вызывает метод без проверки результата.

## Лимит на нити

Не больше 5 🟡 Nit в одном ревью. Остальное — одной строкой в сводке
("+N похожих замечаний по стилю").

## Обязательно проверять

- У новых публичных эндпоинтов есть проверка авторизации/policy, и она
  соответствует нужному уровню доступа (раздел 4.1 ТЗ).
- У новых или изменённых вебхуков — идемпотентность повторной доставки.
- Новые поля с персональными данными не улетают в логи/Sentry как есть.
- Изменения в биллинге проверены применительно к обоим провайдерам (Stripe и
  CloudPayments), а не только к одному.
- Обработка ошибок для новых сценариев соответствует разделу 11 ТЗ (нет
  интернета, таймаут, истёкшая сессия, ошибка сервера — понятные состояния, а
  не необработанное исключение).

## Сводка

Начинай сводку ревью с краткого итога вида "2 критичных, 3 nit" и веди с
"критичных проблем нет", если находок уровня Important нет.
